# MacSafe

[English](README.md) | [简体中文](README.zh-CN.md)

MacSafe 是一款原生 macOS 菜单栏应用，当您离开设备时自动监控周围环境，防止未经授权的访问。

## 功能特性

| 功能 | 说明 |
|------|------|
| **自动激活** | 锁屏、屏保启动或空闲超时时自动开始监控 |
| **摄像头监控** | 以 1fps 低频检测画面运动和人脸靠近，CPU 占用极低 |
| **麦克风监控** | 检测设备附近的突发大声音响 |
| **加速度计监控** | 检测设备被拿起或倾斜（仅 Apple Silicon MacBook） |
| **合盖检测** | 监控 MacBook 翻盖动作 |
| **视频证据** | 触发警报前后自动保存视频片段至 `~/Movies/MacSafe/` |
| **本地通知** | 立即弹出 macOS 系统横幅通知，并播放提示音 |
| **手机推送** | 通过 Pushover 将警报推送到手机（可选） |
| **警报历史** | 浏览历次警报记录及对应的视频片段链接 |
| **极简驻留** | 仅显示在菜单栏，无 Dock 图标，后台资源占用极低 |

## 系统要求

- **macOS 13.0 (Ventura)** 或更高版本
- **Xcode 15.0** 或更高版本（用于编译）
- Apple 开发者账号（用于代码签名）
- 加速度计功能需要 **Apple Silicon MacBook**（M1 或更新）

## 安装与构建

### 方式一：直接用 Xcode 构建（推荐）

1. 克隆仓库：
   ```bash
   git clone <仓库地址>
   cd mac-safe-mode
   ```

2. 打开 Xcode 项目：
   ```bash
   open MacSafe.xcodeproj
   ```

3. 在 Xcode 中选择 `MacSafe` target，进入 **Signing & Capabilities** 标签页，将 **Team** 设置为您的 Apple 开发者账号。

4. 按 `⌘R` 编译并运行。成功后菜单栏右上角会出现一个盾牌图标。

### 方式二：使用 XcodeGen 重新生成项目

如果修改了 `project.yml` 后需要重新生成 `.xcodeproj`：

```bash
brew install xcodegen
xcodegen generate
open MacSafe.xcodeproj
```

## 详细使用教程

### 基本操作

点击菜单栏的盾牌图标，弹出控制面板，面板提供以下操作：

| 按钮 | 说明 |
|------|------|
| **Activate** | 立即手动开始监控 |
| **Deactivate** | 停止监控（暂停状态） |
| **Acknowledge Alert** | 确认当前警报，返回监控状态（仅警报触发时显示） |
| **Settings** | 打开设置窗口 |

---

### 自动激活配置

打开 **Settings → Automatic Activation**：

#### 锁屏时激活
- 开启后，屏幕锁定时 MacSafe 自动进入监控状态。
- 适合离开工位时锁屏的用户（`Control + Command + Q`）。

#### 屏保启动时激活
- 屏保程序启动时自动开始监控。
- 配合「屏保延迟」使用效果更佳（系统设置中设置屏保等待时间）。

#### 空闲超时激活
- 当键盘和鼠标在指定时间内无操作时自动激活。
- 可选时长：1 分钟 / 5 分钟 / 10 分钟 / 30 分钟。
- 适合忘记锁屏但暂时离开的场景。

#### 登录时启动
- 开启后系统启动时 MacSafe 自动运行，无需手动打开。

---

### 传感器设置

打开 **Settings → Sensors**：

#### 摄像头（运动与人脸检测）
- 以每秒 1 帧（1fps）的频率采集画面，使用帧差算法检测运动。
- **人脸检测**（子选项）：在检测到运动后进一步判断是否出现人脸，减少误报。
- 首次启用时系统会弹出摄像头权限请求。

#### 麦克风（声音检测）
- 实时监控环境音量，超过设定分贝阈值时触发警报。
- 适合检测敲击声、说话声等突发噪音。

#### 合盖检测
- 监控 MacBook 翻盖事件，合上后再打开时立即触发警报。
- 适合防止有人趁机打开您的电脑。

#### 运动传感器（加速度计）
- 检测设备被拿起或倾斜（仅支持 Apple Silicon MacBook M1 及以上）。
- 可捕捉从摄像头盲区进行的偷窃行为。
- Intel Mac 上此选项不可用（显示警告图标）。

---

### 灵敏度调节

打开 **Settings → Sensitivity**：

#### 运动阈值（Motion Threshold）
- 滑块范围：2% — 30%
- 默认值：**8%**
- 数值越低，对轻微运动越敏感；数值越高，需要更明显的动作才触发。
- **建议**：
  - 安静环境（无风扇、无窗帘飘动）：可调低至 4–6%
  - 嘈杂/多人环境：调高至 12–20% 减少误报

#### 音量阈值（Audio Threshold）
- 滑块范围：−60 dBFS — −10 dBFS
- 默认值：**−30 dBFS**
- 数值越高（越接近 0），仅极大声音才触发；数值越低，轻微声响即可触发。
- **建议**：
  - 安静办公室：−40 dBFS
  - 嘈杂环境（咖啡馆等）：−20 dBFS

### 视频录制

打开 **Settings → Video Recording**：

MacSafe 采用**滚动预录缓冲**机制：即使尚未触发警报，也持续将最近 N 秒的画面保存在内存中。警报触发后立即将缓冲内容写入文件，并继续录制若干秒收尾。

| 参数 | 可选值 | 说明 |
|------|--------|------|
| **Pre-roll Buffer** | 5 / 10 / 15 / 30 秒 | 警报触发前保留的画面长度 |
| **Post-roll Duration** | 5 / 10 / 15 秒 | 警报触发后继续录制的时长 |

**录像存储位置**：`~/Movies/MacSafe/`，文件名格式为 `YYYY-MM-DD_HH-mm-ss.mov`。

点击 **Open Recordings Folder** 按钮可直接在 Finder 中打开该文件夹。

> 视频文件不会自动删除，请定期手动清理以节省磁盘空间。

### 手机推送通知（Pushover）

Pushover 是一项第三方推送服务，可将警报实时发送到您的 iPhone 或 Android 手机，无需额外服务器。

#### 第一步：注册 Pushover 账号

1. 访问 [pushover.net](https://pushover.net) 注册账号。
2. 在账号主页可以看到您的 **User Key**（用户密钥），记录备用。
3. 在手机上安装 Pushover 客户端（App Store / Google Play），用同一账号登录。

#### 第二步：创建应用 Token

1. 登录 Pushover 网站，进入 [应用注册页面](https://pushover.net/apps/build)。
2. 填写应用名称（如 `MacSafe`），选择类型为 `Application`，点击 **Create Application**。
3. 创建成功后获得 **API Token**，记录备用。

#### 第三步：在 MacSafe 中配置

1. 打开 MacSafe **Settings → Mobile Push Notifications**。
2. 开启 **Enable Pushover notifications**。
3. 将 **User Key** 和 **API Token** 填入对应输入框。
4. 出现绿色"Pushover configured"提示即配置成功。

之后每次触发警报，手机将在数秒内收到推送通知，内容包括警报类型和触发时间。

> 仅警报文字通过 Pushover 发送，不上传任何图片或音频数据。

## 锁屏与休眠下的监控能力

这是安全类应用最关键的问题。以下是 MacSafe 在各种系统状态下的实际表现：

### 各场景能力对照表

| 场景 | 应用进程 | 摄像头 | 麦克风 | 加速度计 | 推送通知 |
|------|---------|--------|--------|---------|---------|
| **锁屏**（Cmd+Ctrl+Q） | ✅ 正常运行 | ⚠️ 见下方说明 | ✅ 正常 | ✅ 正常 | ✅ 正常 |
| **仅熄屏**（显示器关闭，CPU 运行） | ✅ 正常运行 | ⚠️ 见下方说明 | ✅ 正常 | ✅ 正常 | ✅ 正常 |
| **屏保启动** | ✅ 正常运行 | ✅ 正常 | ✅ 正常 | ✅ 正常 | ✅ 正常 |
| **系统休眠**（Sleep） | ⚠️ 进程冻结 | ❌ 不可用 | ❌ 不可用 | ❌ 不可用 | ❌ 不可用 |
| **合盖（无外接显示器）** | ⚠️ 触发休眠 | ❌ | ❌ | ❌ | ❌ |
| **合盖（接外接显示器，蛤蜊模式）** | ✅ 正常运行 | ✅ 正常 | ✅ 正常 | ✅ 正常 | ✅ 正常 |

### 摄像头在锁屏/熄屏时的限制

自 **macOS 14 (Sonoma)** 起，Apple 加强了隐私保护：当显示器关闭（包括锁屏时熄屏）时，`AVCaptureSession` 可能收到系统级中断，摄像头帧采集会暂停。这是 Apple 的硬件隐私保护机制，**不能通过任何软件手段绕过**。

MacSafe 已实现中断自动恢复：
- 摄像头被中断时自动记录日志，不崩溃
- 屏幕重新亮起/解锁后，摄像头自动重启并恢复监控

在摄像头不可用期间，**麦克风和加速度计仍然持续工作**，可检测声音和设备移动。

### 系统休眠期间

macOS 进入完整休眠（System Sleep）时，CPU 停止执行代码，所有传感器停止工作。这是操作系统级别的限制，无法绕过。

**唤醒后的行为**（已修复的 bug）：
- 从休眠唤醒时，MacSafe 自动检测屏幕是否仍处于锁定状态
- 如果仍然锁屏：传感器立即恢复运行（修复前的版本会错误地停止传感器）
- 如果已解锁：正常退出监控状态

### 阻止系统休眠（可选）

在 **Settings → Automatic Activation** 中开启 **"Prevent system sleep while monitoring"** 选项：

- MacSafe 在监控期间持有系统电源断言（`idleSystemSleepDisabled`）
- Mac 不会因空闲而自动进入休眠，确保麦克风和加速度计持续工作
- 显示器仍可正常熄屏（降低亮度节能），但 CPU 保持运行
- 仅在监控激活期间生效，停止监控后电源断言立即释放

> 注意：此选项会增加电池消耗，建议仅在接电源时或需要长时间无人值守监控时启用。

## 工作原理

### 状态机

MacSafe 内部运行一个严格的状态机，共四种状态：

```
.idle（空闲）
  │
  ├─[锁屏 / 屏保 / 空闲超时 / 手动激活]──► .monitoring（监控中）
  │                                              │
  │           ┌──────────────────────────────────┘
  │           │ [运动 / 人脸 / 声音 / 合盖 / 设备移动]
  │           ▼
  │        .alerting（警报中）
  │           │
  │           └─[确认 / 超时 30s]──► .monitoring（继续监控）
  │
  ├─[解锁 / 用户活动]◄──────────────── 任意状态
  │
  └─[手动禁用]──► .suspended（已暂停）
                     │
                     └─[手动激活]──► .monitoring
```

### 运动检测流水线

1. 摄像头以 1fps 采集画面（CPU 占用极低）
2. 将帧缩小至 160×120 像素（GPU 加速）
3. 转换为灰度图
4. 与上一帧做像素差值运算
5. 计算差值均值，归一化到 0.0–1.0
6. 时序平滑：`score = 0.7 × 上次 + 0.3 × 当前`
7. 分数超过阈值时触发运动警报，同时启动人脸检测

## 状态说明

菜单栏图标颜色含义：

| 颜色 | 状态 | 说明 |
|------|------|------|
| 灰色 | 空闲 | 正常待机，未监控 |
| 蓝色（脉冲） | 监控中 | 传感器运行中，等待触发 |
| 红色（脉冲） | 警报中 | 已检测到异常，正在发送通知 |
| 黄色 | 已暂停 | 手动禁用，不会自动激活 |

## 隐私说明

- 所有摄像头和麦克风数据均**在本地处理**，绝不上传至任何服务器。
- 视频片段保存在本地 `~/Movies/MacSafe/`，不会自动分享。
- 若配置了 Pushover，仅发送包含警报类型和时间的**纯文本消息**，不含图片或音频。
- 应用不收集任何使用数据或遥测信息。

## 常见问题

**Q：为什么摄像头指示灯没有亮起？**
A：MacSafe 以 1fps 低频采样，某些 Mac 的摄像头指示灯可能显示为非常暗或间歇闪烁，这是正常现象。

**Q：误报太多怎么办？**
A：在 Settings → Sensitivity 中适当提高运动阈值（如从 8% 调至 15%），或同时开启"人脸检测"，只有检测到人脸时才触发警报。

**Q：运动传感器选项显示警告图标？**
A：加速度计功能仅支持搭载 Apple Silicon（M1 及以上）的 MacBook，Intel Mac 无此传感器。

**Q：收不到 Pushover 推送？**
A：请确认 User Key 和 API Token 均填写正确，且手机上已安装 Pushover 客户端并登录同一账号。同时检查手机通知权限是否已授权给 Pushover。

**Q：录像文件保存在哪里？**
A：`~/Movies/MacSafe/` 目录下，文件名格式为 `2024-01-15_14-30-22.mov`。

**Q：合盖后还能监控吗？**
A：合盖且无外接显示器时，Mac 会进入休眠，所有传感器暂停。若连接外接显示器（蛤蜊模式），Mac 保持唤醒，MacSafe 完全正常工作。开启"Prevent system sleep while monitoring"可防止 Mac 因空闲自动休眠，但无法阻止合盖引起的休眠。

**Q：锁屏后摄像头还能工作吗？**
A：macOS 14+ 可能在显示器关闭时中断摄像头会话（隐私保护机制）。MacSafe 会自动处理中断并在屏幕亮起后恢复。锁屏期间麦克风和加速度计持续工作。

**Q：系统休眠唤醒后监控会自动恢复吗？**
A：是的。MacSafe 在唤醒时会检测屏幕是否仍处于锁定状态，若仍锁屏则立即恢复传感器运行，无需手动操作。

**Q：如何完全卸载？**
A：退出 MacSafe，删除应用程序文件，同时可删除 `~/Movies/MacSafe/` 目录清除录像。偏好设置存储在 `~/Library/Preferences/com.macsafe.app.plist`，可手动删除。

## 项目架构

```
MacSafeApp (@main)
  └── AppDelegate（NSStatusItem 菜单栏 + NSPopover）
        └── MonitoringCoordinator（核心 ObservableObject）
              ├── MonitoringStateMachine（actor，纯状态转换）
              ├── ScreenStateMonitor    （DistributedNotificationCenter 监听锁屏/屏保）
              ├── IdleMonitor           （IOKit HIDIdleTime 轮询）
              ├── CameraService         （AVFoundation，1fps 采集）
              │     ├── MotionDetector  （CIFilter 帧差算法）
              │     └── FaceDetector    （Vision VNDetectFaceRectanglesRequest）
              ├── VideoRecorder         （AVAssetWriter 滚动环形缓冲区）
              ├── AudioMonitor          （AVAudioEngine + Accelerate vDSP RMS）
              ├── AccelerometerMonitor  （CoreMotion CMMotionManager）
              └── AlertService          （UNNotification + Pushover + 历史记录）
```

### 使用的系统框架

| 框架 | 用途 |
|------|------|
| AVFoundation | 摄像头采集与视频录制 |
| Vision | 人脸检测 |
| CoreImage | GPU 加速帧差运算 |
| UserNotifications | 本地推送通知 |
| IOKit | 系统空闲时间检测 |
| Accelerate | 音频 RMS 快速计算 |
| CoreMotion | 加速度计数据读取 |
| Combine | 响应式事件流管道 |
| ServiceManagement | 登录时启动（macOS 13+） |
